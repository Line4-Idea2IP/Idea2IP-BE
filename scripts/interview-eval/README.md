# 인터뷰 실제 모델 회귀 검사

인터뷰 로직이나 프롬프트를 바꾼 뒤, 실제 모델로 정해진 시나리오를 여러 번 돌려 기대 결과와 비교합니다.
단위 테스트(스텁 모델)는 코드 경로만 확인하므로, 모델 판정에 영향을 주는 변경은 이 검사를 통과해야 병합합니다.

## 준비

- 백엔드가 `idea2ip.interview.question-mode=live`로 실행 중이고, 데스크탑 모델(llama.cpp)에 연결되어 있어야 합니다.
- Python 3.9 이상. 표준 라이브러리만 씁니다.
- 실행할 때마다 테스트 계정과 프로젝트를 새로 만듭니다. 그래서 기본값으로는 `localhost` 서버에만 실행됩니다.
  배포 서버에서 돌리려면 `--allow-remote`를 함께 지정해야 합니다.

## 실행

```bash
python -I scripts/interview-eval/run_eval.py --base-url http://127.0.0.1:18081 --runs 3
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--base-url` | `http://127.0.0.1:18081` | 백엔드 주소 |
| `--runs` | `3` | 시나리오마다 반복 횟수 |
| `--scenario` | 전체 | 특정 시나리오만 실행 (여러 번 지정 가능) |
| `--phase` | `0` | 이 단계까지의 시나리오가 실패하면 종료 코드 1 |
| `--image` | 생성한 단색 PNG | 첨부할 PNG/JPEG |
| `--out` | `build/interview-eval/<시각>` | 결과 폴더 |
| `--allow-remote` | 끔 | localhost가 아닌 서버 허용 |

## 결과

결과 폴더에 다음 파일이 남습니다.

- `summary.md`: 시나리오별 통과 횟수와 실패한 검사, 실행별 질문 순서
- `summary.json`: 같은 내용의 JSON
- `<시나리오>-run<번호>.json`: 실행별 전체 기록 (시작 전 상태, 질문·답변·HTTP 상태·소요 시간, 최종 상태, 메시지)

## 검사 항목

| 검사 | 실패 조건 |
|---|---|
| 모든 요청 첫 시도 성공 | 답변 제출이나 인터뷰 시작이 첫 시도에 200/201이 아님 (503 포함) |
| 인터뷰 완료 | 최종 상태가 `COMPLETED`가 아님 |
| 물어야 할 항목을 물음 | 시나리오의 `mustAsk` 항목을 한 번도 묻지 않음 |
| 생략해야 할 항목을 묻지 않음 | 시나리오의 `mustSkip` 항목을 물음 |
| 다시 물어야 할 항목을 다시 물음 | `minAsks` 횟수보다 적게 물음 |
| 이미 답한 항목을 다시 묻지 않음 | `maxAsks` 횟수보다 많이 물음 |
| 첫 질문에 프로젝트 이름이나 요소가 들어감 | `mustMention` 항목의 첫 질문에 지정한 낱말이 하나도 없음 |
| 한 항목 최대 3회 | 한 항목을 4번 이상 물음 |
| 최종 항목 상태 / 시작 전 항목 상태 | `expectFinal` / `expectReadiness`와 다름 |
| 최종 항목 요약 | 최종 요약이 `expectSummary`와 다름 (도구 확인 질문 뒤 ‘Sora’로 정리됐는지 등) |
| 같은 질문 반복 없음 | 공백과 문장부호를 뺀 질문 문장이 같은 질문이 두 번 나옴 |
| 같은 요청 ID 재전송 시 중복 저장 없음 | 첫 답변을 같은 요청 ID로 다시 보냈을 때 다른 답변 ID나 다른 다음 질문이 돌아옴 |
| 질문 속 인용은 사용자 원문 | 질문의 따옴표 안 문장이 앞선 답변에 없음 |
| 자동 완료 근거는 원문이고 다른 항목과 겹치지 않음 | 묻지 않고 완료된 항목의 근거가 답변에 없거나, 다른 항목의 근거와 같은 문장임 |

## 시나리오 추가

`scenarios.json`의 `scenarios`에 항목을 추가합니다. 지정하지 않은 값은 `defaults`를 씁니다.

- `answers`: 항목별 답변 목록. 같은 항목을 다시 물으면 다음 답변을 쓰고, 목록이 끝나면 마지막 답변을 반복합니다.
- `phase`: 이 시나리오가 통과해야 하는 재설계 단계. `--phase`보다 큰 시나리오는 실행하되 ‘예정’으로 표시하고 종료 코드에 반영하지 않습니다.
- `mustAsk`, `mustSkip`, `minAsks`, `maxAsks`, `mustMention`, `expectFinal`, `expectSummary`, `expectReadiness`: 위 검사의 기대 결과.

시나리오는 실제로 문제가 났던 입력에서 만듭니다. 오판을 고칠 때는 먼저 그 입력을 시나리오로 추가해 실패하는 것을 확인한 뒤 고칩니다.
